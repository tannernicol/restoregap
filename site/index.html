Prove your recovery works — then refuse the risky change until it does.

Your nightly backup job says success. Restore Gap restores that backup for real, in a sandbox, checks the result, and refuses the destructive change — yours or your coding agent's — until that proof exists and is fresh. One static binary, MIT, no account, no phone-home.

Watch it work

Three commands, each one earning the next

check

restoregap check proj backup/proj
tree: 3 live / 2 recovery — 1 MISSING FROM RECOVERY, 2 STALE IN RECOVERY
  these exist in exactly one place:
    .env
  these exist in both but the recovery copy is out of date:
    app.conf
    app.db

Zero config. Exit 1 on drift. Compares directory trees today; restic, borg and ZFS comparators are built in vote order (issue #2).

drill

restoregap drill
✓ app-db-recovery — data-valid (L3) in 0s: integrity ok; users=95 (>= 90% of live 100 = 90)

A real restore into a sandbox with typed checks. Levels are honest: restores (files present) → data-valid (typed checks passed) → serves (booted and answered).

preflight

restoregap preflight --intent rm-app-db.yml
BLOCK — Restore Gap blocked this change. Supply proof, change the plan, or record an owner override.
  - Refresh or supply proof "app-db-recovery", or record an owner override before proceeding.

Fail-closed. Every verdict, proof and owner override lands in a hash-chained ledger you can verify.

What a "backup exists" check cannot tell you

  • Existing is not restorable

    A backup that cannot be restored is a file, not a safety net.

  • Unreachable is not failed — and neither is stale

    The author's own credential store: 1,303 live entries vs 1,300 sealed → reported as drift, not "backup OK".

  • A proof has a half-life

    Proofs expire; attestations nobody re-observes go cold.

  • Direction matters

    Newer-in-live vs newer-in-recovery need opposite fixes.

  • Races are real

    A drill 25 seconds before the nightly regen fails honestly and wrongly.

The full list, each one a bug found in dogfood → docs/why-not-a-script.md

Built for the riskiest operator: your coding agent

A PreToolUse hook turns rm, mv, truncate, dd, shred, git push --force, terraform destroy and dropdb into intents and asks preflight before the shell runs. Restore Gap is the reason to allow a guarded change; your agent's own deny rules or sandbox are the general net.

echo '{"tool_name":"Bash","tool_input":{"command":"rm proj/app.db"}}' | preflight-hook.sh
# BLOCK
echo $?  # 2 — the agent's rm never runs

How the agent gate works → docs/agent-gate.md

Same gates over MCP: restoregap mcp serve.

Install

curl -sSfLO https://raw.githubusercontent.com/tannernicol/restoregap/v0.10.0/scripts/install.sh
less install.sh && sh install.sh   # pinned tag; verifies checksums; ~/.local/bin; never sudo

Linux and macOS, amd64 and arm64. Every release ships checksums.txt and SBOMs; builds are reproducible. Or: go install github.com/tannernicol/restoregap/cmd/restoregap@latest
